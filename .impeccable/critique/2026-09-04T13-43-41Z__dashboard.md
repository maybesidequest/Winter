## Design Specificity Verdict

InterChat's creative north star in `DESIGN.md` is **"The Connected Atlas"**: a nocturnal, tactile operations room where Discord communities are distinct territories, connections are deliberate routes, and controls use layered surfaces, crisp lower edges, and controlled violet/sky/sage/coral signals.

When evaluated across the 7 target surfaces, the interface exhibits a **bipolar design identity**:

* **Authentic "Connected Atlas" Surfaces:**
  * `HubRoutes.tsx` and `ConnectChannelWizard.tsx` embody the vision. They feature custom bridge cards with squircle initials, tactile edge depth, status badges, operation notices (`ConnectionOperationNotice`), and a spatial route connector (`[Hub] ── [Route] ── [#channel]`) that grounds relational foreign keys in a tangible network map.
  * `HubRulesPanel.tsx` uses custom monospace rule badges (`#1` with `#5b4ccb` tactile depth shadow), elevated cards, and dedicated empty-state iconography.
* **Generic Admin / Stock Ant Design Relapse:**
  * `activity.tsx`: A complete relapse into generic Ant Design boilerplate (`<Alert>`, `<Card>`, `<Col>`, `<Row>`, `<Select>`, `<Statistic>`, `<List>`, `<Empty>`, `<Skeleton>`). It reads like an off-the-shelf component library tutorial rather than an InterChat operations room.
  * `help.tsx`: Mixes raw Ant Design cards, `<Input.Search>`, form items, and message toasts with an inline glass container.
  * `appeals.tsx`: Uses default Ant Design lists, `<Tag color="red">`, and stock modals, abandoning the tactile nocturnal aesthetic.
  * `HubSafetySettingsPanel.tsx`: Regresses entirely to unstyled native HTML `<input type="checkbox">` elements, directly violating the mandatory Flat-Depth `DepthToggle` standard defined in `AGENTS.md` and `DESIGN.md`.
* **Under-Authored Placeholder Surfaces:**
  * `DashboardHome.tsx`: Contains only two oversized metric cards and an activity banner. It provides no atlas view, no bridge topology, no live relay status, and no quick connect actions. Production users don't even see the "Explore Hubs" header button (which is guarded behind `import.meta.env.DEV`).

## Overall Impression

InterChat possesses a compelling creative north star in "The Connected Atlas" and rock-solid control-plane engineering (pervasive `idempotencyKey`UUIDs, version-based concurrency checks, and async operation polling in `ConnectionOperationNotice`). However, the experience suffers from an acute visual split. The primary operational routes (`HubRoutes`, `HubRulesPanel`) feel bespoke and tactile, while secondary user routes (`activity.tsx`, `help.tsx`, `appeals.tsx`) and settings panels regress to generic Ant Design components and unstyled native HTML inputs. Establishing design parity across all 7 surfaces will instantly transform InterChat into a cohesive, tier-one control plane.

## What's Working

1. **ConnectChannelWizard's Routing Topology:**
   The multi-step wizard with the visual bridge route diagram (`[Hub] ── [Discord] ── [#channel]`) grounds the user in the spatial "Connected Atlas" concept, turning an abstract relational link into an intuitive geographic connection.
2. **Resilient Asynchronous Operation Handling (`ConnectionOperationNotice`):**
   Decoupling user actions from async background execution with 2-second polling, terminal status auto-dismissal (30s), and semantic tone mapping (`info`, `success`, `warning`, `danger`) is exemplary control-plane engineering.
3. **Pervasive Idempotency & Concurrency Guardrails:**
   Across `HubRoutes`, `HubRulesPanel`, `HubModerationPanel`, and `ConnectChannelWizard`, mutations rigorously enforce `expectedVersion` and `idempotencyKey: crypto.randomUUID()`. This guarantees network retries and concurrent moderator actions cannot corrupt state.

## Priority Issues (P0 - P3)

### [P0] Detached Global Appeal Resolution Reason Causing Accidental Misattribution
* **Surface:** `app/components/dashboard/HubModerationPanel.tsx` (Lines 143–151)
* **Why it matters:** A single text input `#appeal-resolution-reason` sits above the entire list of pending appeals. When a moderator clicks "Approve" or "Reject" on any appeal row below, that input's value is silently attached. In an active moderation session, typing a custom justification for Appeal A and subsequently clicking Appeal B attaches the wrong audit justification permanently to Appeal B.
* **Fix:** Move the resolution reason into a dedicated modal or drawer per appeal (or expandable card) with an explicit confirmation step showing the appeal reason, applicant, and resolution input together.
* **Suggested Command:** `/impeccable layout app/components/dashboard/HubModerationPanel.tsx`

### [P1] Stock Ant Design Relapse on Secondary Pages
* **Surfaces:** `app/routes/dashboard/activity.tsx`, `app/routes/dashboard/help.tsx`, `app/routes/dashboard/appeals.tsx`
* **Why it matters:** Direct usage of unstyled Ant Design components (`Card`, `Statistic`, `Select`, `List`, `Skeleton`, `Form`, `Input.Search`) completely bypasses the Connected Atlas design language, Sora typography, and Flat-Depth tokens. Operators navigate from a polished nocturnal dark control plane into a standard white Ant Design admin demo.
* **Fix:** Replace Ant Design components with InterChat design primitives (`DashboardSectionCard`, custom Flat-Depth inputs, Sora headers, thematic empty states, and URL search state).
* **Suggested Command:** `/impeccable polish app/routes/dashboard/activity.tsx`

### [P1] Non-Compliant Native HTML Checkboxes in Hub Safety Settings
* **Surface:** `app/components/dashboard/moderation/HubSafetySettingsPanel.tsx` (Line 13)
* **Why it matters:** Safety feature flags use unstyled `<input type="checkbox">` elements instead of the mandatory `<DepthToggle>` component defined in `AGENTS.md` and `DESIGN.md`. This violates project standards, provides inadequate touch targets, lacks accessible switch semantics (`role="switch"`, `aria-checked`), and visually clashes with the control plane.
* **Fix:** Replace checkboxes with `<DepthToggle checked={draft[key]} onChange={(checked) => ...} />`, format the panel with proper card elevation, and group toggles into semantic categories (Content, Spam, Media).
* **Suggested Command:** `/impeccable polish app/components/dashboard/moderation/HubSafetySettingsPanel.tsx`

### [P2] Hollow Dashboard Home Page Lacking Operational Awareness
* **Surfaces:** `app/routes/dashboard/index.tsx`, `app/components/dashboard/DashboardHome.tsx`
* **Why it matters:** The primary dashboard landing page contains only two static count cards ("Hubs you manage: N", "Servers you manage: N") and hides the explore link behind a DEV flag. For a control plane called "Connected Atlas", the home page offers zero operational status, no bridge health alerts, no message volume indicators, and no fast actions.
* **Fix:** Redesign `DashboardHome` as an Atlas Command Overview: live bridge health summary, quick-action rail ("Connect Server", "Review Appeals"), and recent network audit log snippet.
* **Suggested Command:** `/impeccable shape app/components/dashboard/DashboardHome.tsx`

### [P2] Incongruous Slack Icon in Discord Bridge Wizard
* **Surface:** `app/components/dashboard/connection/ConnectChannelWizard.tsx` (Line 373)
* **Why it matters:** The icon used in the review step route diagram is `<SlackOutlined />` from `@ant-design/icons` to represent a Discord channel bridge. For a dedicated Discord control plane, using a competitor's logo erodes credibility and user trust.
* **Fix:** Replace `<SlackOutlined />` with a custom Discord SVG mark or appropriate network/channel glyph (`<ApartmentOutlined />` or `#` route glyph).
* **Suggested Command:** `/impeccable clarify app/components/dashboard/connection/ConnectChannelWizard.tsx`
